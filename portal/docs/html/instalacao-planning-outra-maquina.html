Planning 2.0 - Instalacao em Outra Maquina

Documento operacional para preparar uma nova estacao, instalar dependencias, configurar acesso Oracle/VPN e subir o portal localmente com frontend + backend.

Stack: React + Vite + Express Banco: Oracle Portas padrao: 5173 e 5000 Sistema alvo: Windows

Sumario

1. Premissas 2. Dependencias 3. Instalacao do Projeto 4. Configuracoes Necessarias 5. Execucao da Aplicacao 6. Validacao Pos-Instalacao 7. Atalho Operacional 8. Troubleshooting

1. Premissas

  • Usuario com permissao de instalacao local e execucao de scripts.
  • Acesso ao repositorio com a pasta portal.
  • Acesso de rede ao Oracle no host 10.129.181.131:1521.
  • Quando aplicavel, VPN corporativa conectada na faixa 10.108.110.x.
  • Portas 5173 (frontend) e 5000 (backend) livres na maquina local.
Observacao: o backend tenta habilitar Oracle Thick Mode automaticamente. Se nao encontrar client local, segue em Thin Mode. Em ambiente Oracle legado, priorizar Instant Client instalado.

3. Instalacao do Projeto

3.1 Clonar ou copiar o projeto

git clone <url-do-repositorio> cd "Planning 2.0/portal"

3.2 Instalar dependencias

npm install

3.3 Conferir scripts disponiveis

npm run

Devem existir pelo menos os scripts: dev e server.

4. Configuracoes Necessarias

4.1 Oracle e conectividade

  • Arquivo de backend: portal/server.js.
  • Credenciais e connectString estao definidos no objeto ORACLE_CONFIG.
  • Validar acesso ao host Oracle e liberacao de firewall.
  • Se a rede exigir VPN, confirmar IP local na faixa 10.108.110.x.

4.2 Proxy frontend para backend

  • Arquivo: portal/vite.config.ts.
  • Proxy esperado: /api apontando para http://127.0.0.1:5000.

4.3 Estrutura do projeto

  • Manter estrutura completa da pasta portal.
  • Todos os dados são consumidos do banco compartilhado — não há dependência de arquivos locais.

5. Execucao da Aplicacao

5.1 Subir backend (API)

npm run server

5.2 Subir frontend (Vite)

npm run dev

5.3 Acesso no navegador

http://localhost:5173
Quando ambos os processos estiverem ativos, a interface deve carregar e consumir rotas /api via proxy local.

6. Validacao Pos-Instalacao

  1. Abrir http://localhost:5173.
  2. Verificar status de conexao no portal.
  3. Testar carregamento de perfis, squad e feriados.
  4. Confirmar ausencia de erro Oracle no terminal do backend.

Comandos de verificacao rapida (PowerShell)

Test-NetConnection localhost -Port 5000 Test-NetConnection localhost -Port 5173

7. Atalho Operacional

Para facilitar o uso na nova maquina, pode ser utilizado o atalho operacional criado no projeto raiz: Portal Gestao e Planejamento.lnk.

  • Se API e frontend nao estiverem ativos: inicia npm run server e npm run dev.
  • Se ja estiverem ativos: apenas abre o navegador na URL do portal.

Arquivos relacionados:

  • start-portal.ps1
  • Portal Gestao e Planejamento.cmd
  • Portal Gestao e Planejamento.lnk

8. Troubleshooting

8.1 Erro no modulo oracledb

  • Instalar/reinstalar Oracle Instant Client compativel.
  • Validar variaveis de ambiente Oracle se Thick Mode for exigido.
  • Executar npm install novamente apos ajuste de ambiente.

8.2 Porta em uso

Get-NetTCPConnection -LocalPort 5000,5173 -State Listen
  • Encerrar processo conflitante ou ajustar porta local.

8.3 Falha de conexao com banco

  • Confirmar VPN ativa (quando necessaria).
  • Validar rota para 10.129.181.131:1521.
  • Revisar credenciais no ORACLE_CONFIG.
