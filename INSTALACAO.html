Planning 2.0 - Guia de Instalação

Procedimento completo para instalar e configurar Planning 2.0 em uma nova máquina. Arquitetura client-server com banco de dados compartilhado em rede.

Stack: React + Vite + Express Banco: Oracle compartilhado Portas: 5173 e 5000 OS: Windows

Sumário

1. Premissas 2. Dependências do Sistema 3. Instalação de Dependências 4. Setup do Projeto 5. Configuração do Banco 6. Execução Local 7. Atalho de Inicialização 8. Troubleshooting

1. Premissas

  • Usuario com permissao de instalacao local.
  • Acesso ao repositorio do projeto.
  • Acesso de rede ao servidor Oracle corporativo (10.129.181.131:1521).
  • VPN corporativa ativa quando necessario (faixa 10.108.110.x).
  • Portas locais 5173 (frontend) e 5000 (backend) disponiveis.
  • Credenciais Oracle fornecidas pela equipe de infraestrutura.
Nota importante: Planning 2.0 é uma aplicação client-server pura. Não há dependência de arquivos locais (.xlsm, arquivos de configuração embarcados). Todos os dados são consumidos da base compartilhada em rede.

2. Dependências do Sistema

Componente Versão recomendada Link de download
Node.js 22 LTS nodejs.org
npm 10+ Incluído com Node.js
Git Atual git-scm.com
Oracle Instant Client (opcional) Compatível com seu Oracle Oracle Downloads

3. Instalação de Dependências

3.1 Node.js e npm

  1. Acessar https://nodejs.org/
  2. Baixar LTS (22.x)
  3. Instalar seguindo o wizard padrão
  4. Validar instalação no PowerShell:
    node --version npm --version

3.2 Git

  1. Acessar https://git-scm.com/
  2. Baixar versão para Windows
  3. Instalar com configurações padrão
  4. Validar:
    git --version

3.3 Oracle Instant Client (recomendado)

  • Visitar Oracle Instant Client Downloads
  • Baixar versão x64 compatível com seu servidor Oracle
  • Descompactar em local sem espaços (ex: C:\Oracle\instantclient)
  • Adicionar ao PATH do Windows se desejar Thick Mode

4. Setup do Projeto

4.1 Clonar repositório

git clone <url-do-repositorio> cd "Planning 2.0/portal"

4.2 Instalar dependências npm

npm install

4.3 Verificar scripts disponíveis

npm run

Esperado: dev e server como scripts principais.

5. Configuração do Banco

5.1 Credenciais Oracle

  • Arquivo: portal/server.js
  • Objeto: ORACLE_CONFIG
  • Campos:
    • user — usuário Oracle
    • password — senha
    • connectString — string de conexão ao servidor
  • As credenciais padrão são fornecidas pela equipe de infraestrutura

5.2 Detecção automática de VPN

  • O backend detecta automaticamente IP VPN na faixa 10.108.110.x
  • Se conectado, usa IP local como localAddress
  • Sem ação necessária do usuário

5.3 Teste de conectividade

npm run server

Verificar no console: "Oracle client Thick mode successfully enabled" ou "Thin mode fallback".

Acessar http://localhost:5000/api/connection-status para validar conexão ao banco.

6. Execução Local

6.1 Terminal 1: Backend API

npm run server

Esperado: servidor Express rodando em http://127.0.0.1:5000

6.2 Terminal 2: Frontend (Vite)

npm run dev

Esperado: aplicação Vite rodando em http://localhost:5173

6.3 Acessar no navegador

http://localhost:5173
Quando ambos estiverem ativos, a aplicação carregará dados diretamente do banco compartilhado via API REST proxy.

7. Atalho de Inicialização

Um atalho operacional facilita o startup combinado. Localizado na raiz do projeto:

  • Portal Gestao e Planejamento.lnk — atalho Windows
  • Portal Gestao e Planejamento.cmd — launcher batch
  • start-portal.ps1 — script PowerShell de orquestração

Comportamento do atalho

  1. Verifica se aplicação já está rodando na porta padrão (5173)
  2. Procura por processos node em portas alternativas
  3. Se encontrar ativa: abre navegador nela
  4. Se não encontrar: inicia npm run server e npm run dev
  5. Aguarda inicialização (timeout 90s)
  6. Abre navegador em http://localhost:5173

8. Troubleshooting

8.1 Erro ao conectar Oracle

  • Validar conectividade de rede: ping 10.129.181.131
  • Confirmar VPN ativa se necessario
  • Revisar credenciais em server.js
  • Verificar se Oracle Instant Client está instalado (se Thick Mode desejado)

8.2 Porta em uso

Get-NetTCPConnection -LocalPort 5000,5173 -State Listen
  • Se portas estiverem ocupadas, encerrar processo conflitante
  • Ou ajustar variáveis no script start-portal.ps1

8.3 npm install falha

  • Limpar cache: npm cache clean --force
  • Deletar node_modules e package-lock.json
  • Reinstalar: npm install

8.4 Aplicação carrega mas sem dados

  • Verificar se backend está rodando: http://localhost:5000/api/connection-status
  • Revisar console do navegador (F12) para erros CORS ou conexão
  • Confirmar que banco de dados está acessível da máquina
